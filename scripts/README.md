# Scripts

| Script | What it does | How to run |
|---|---|---|
| `check-bundle.mjs` | Post-build guard: the bundle exists where packaging expects it, the renderer's HTML and CSS name no remote origin, the CSP shipped, the three type families were emitted locally, and every packaging glob matches something | `npm run check:bundle` (after `npm run build:app`) |
| `check-stdout-discipline.mjs` | Fails if anything under `core/src` writes to stdout outside `core/src/proto/transport.rs`. stdout carries protocol frames and nothing else | `npm run lint:stdout` |
| `check-style-tokens.mjs` | Criterion 46: the renderer stylesheet declares no colour outside `tokens.css`, no `var(--x)` that is not declared there, and no duration or timing function §11.6 does not carry. Also R35(b): every `@keyframes` name is declared exactly once, and `viewIn`, `panelIn`, `turnIn` only in `styles/base.css`. Prints what it scanned and fails on an empty scan | `npm run lint:style` |
| `check-type-scale.mjs` | Criterion 60: no rendered size below 7px, every size on §8.7's scale, and every tracked size shipping with its letter-spacing. Prints what it scanned and fails on an empty scan | `npm run lint:type` |
| `check-focus-ring.mjs` | Criterion 53: `outline: none` with no inset `box-shadow` ring in the same rule is a build failure — `clip-path` deletes the outline. Prints what it scanned and fails on an empty scan | `npm run lint:focus` |
| `check-shell-accelerators.mjs` | Criterion 61: the Windows system window menu's accelerator is never a literal in the shell — neither in `app/src/main`'s source nor in the built main bundle — and `globalShortcut.register` is never called with a string literal. It reaches the binder only as a chord the user recorded. Prints both counts and fails on an empty scan | `npm run lint:accelerators` (after `npm run build:app`) |
| `package.mjs` | Packaging entry point: reports the signing posture, passes a configured publisher name, and invokes the packager without a shell | `npm run package:dir`, `npm run package:win`, or `npm run package:linux` |
| `check-packaging.mjs` | Post-pack guard: required targets and hooks remain configured, target-specific binaries were staged, and the packed manifest names the built main process | `npm run check:packaging` (after `npm run package:dir`) |
| `stage-worker.mjs` | Validates a 64-bit little-endian Linux ELF, derives its architecture, and stages the worker carried by a Windows installer | `node scripts/stage-worker.mjs --from <path> [--arch x64\|arm64]` |
| `preflight.mjs` | What a build needs before it starts — this platform's native bindings and runnable bin entries, the Node floor, cargo, and the git floor — and the command that repairs each. Names the remedy, not the symptom | imported by `build-dist.mjs` |
| `build-dist.mjs` | The whole build for the host platform: preflight, codegen, the core, the gates, the packager, the post-pack guard, then the artifact list with sizes and SHA-256 sums. Refuses a cross-compile. Every step's output goes to a file under `dist/logs/`, never through a pipe | `npm run dist` |
| `build-dist.sh` · `build-dist.cmd` | Thin wrappers: locate the repository from their own path, check `node` resolves, and hand over to `build-dist.mjs`. The logic lives in one file so the two platforms cannot drift | `bash scripts/build-dist.sh` · `scripts\build-dist.cmd` |
| `win-prepare.mjs` | Makes a WSL-installed `node_modules` usable from Windows too: mirrors every linux native binding to a same-version win32 one, and writes the `.cmd` shims `cmd.exe` needs. **Run after any `npm install` done from WSL** | `npm run prepare:win` |

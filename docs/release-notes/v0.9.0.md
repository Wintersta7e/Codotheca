# Codotheca 0.9.0

The first tagged build, and a pre-release. Everything here was built by this repository's release
workflow from the tagged commit: a Windows installer and a portable `.exe`, and for Linux an
AppImage, a `.deb` and an `.rpm`.

## Before you run it

- **The artifacts are unsigned.** There is no code-signing certificate, by decision, and the
  packager reports `signing=none` rather than implying otherwise. On Windows, SmartScreen shows
  *"Windows protected your PC"*; **More info → Run anyway** starts the app. The warning is about
  the missing signature. Verify the download below rather than trusting it or clicking past it.
- **There is no updater.** No update channel, no update server, no background update traffic. A
  fix reaches you when you download the next release, and only the most recent release is
  supported.

## Verify the download

- `SHA256SUMS` sits beside the artifacts. On Linux, `sha256sum --check --ignore-missing
  SHA256SUMS`; on Windows, `Get-FileHash <file>` and compare the hash with its line.
- `gh attestation verify <file> --repo <this repository>` proves the file was built by this
  repository's release workflow from the tagged commit; it says nothing about whether the code is
  safe.

## Where your library lives

- **The portable `.exe` and the installed build share one library.** On the release run both
  wrote `%APPDATA%\codotheca`, so two copies in two folders are not two libraries.
  `CODOTHECA_DATA_DIR` overrides the location.
- **Uninstalling the app keeps your library.** On the release run the uninstaller removed the
  program and left the index in place.
- The portable build unpacks itself into `%TEMP%` while it runs, about 920 MB on a release run,
  and removes it when it quits: after the release run's clean quit, nothing it wrote was left
  there.

## Linux needs glibc 2.35 or newer

The release run read the glibc version every packed binary needs. The app itself needs at most
**2.35**, for the core; the Electron shell needs 2.25 and its libraries 2.17 or less. So 0.9.0 runs
on a Linux system with glibc 2.35 or newer; `ldd --version` prints yours. The worker Codotheca
installs into a WSL distribution to read projects kept there needs 2.34 on x64 and 2.39 on Arm. This
build is measured, not held to a floor. 1.0 will be built to run on glibc 2.35.

## Known limits

- **Uninstall is refused wherever the recycle bin cannot be shown to take the copy.** Uninstall
  moves a working copy to the recycle bin and never deletes it outright. On Windows, where the
  drive's recycle-bin settings cannot be read, or the bin is turned off, too small for the copy,
  or absent (a network drive), Uninstall is refused and names the reason, for example *"I could
  not read this drive's recycle-bin settings, so I will not uninstall this copy."* On the Windows
  machine this was developed on the settings read as unreadable, so expect this. Measuring what
  the bin does in each case is 1.0's work.
- **No performance figures are published.** Every performance criterion is recorded as
  unmeasured rather than given a plausible budget.

## Reporting a problem

Report a vulnerability privately through the repository's Security tab; [`SECURITY.md`](../../SECURITY.md)
says what is in scope. Anything else is an issue.
